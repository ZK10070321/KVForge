# Day 2 复习：训练、恢复与生成问答

先掌握数据、loss 与更新，再复习验证与恢复，最后学习生成。每题包含完整标准答案与易错点。
代码：[数据](../../kvforge/data.py)、[准备入口](../../prepare_data.py)、[训练辅助](../../kvforge/training.py)、[训练](../../train.py)、[生成](../../generate.py)、[测试](../../tests/test_day2.py)。

## 1. 【必会】字符数、token 数和词表大小有何区别？

答：当前按字符编码，重复字符在序列中重复出现，但只占一个词表条目。训练文本长 859 个字符、包含 34 种不同字符，则序列长度为 859，加上 ID 0 的未知字符槽位，词表大小为 35。

易错：859 不是不同类别数量；本项目字符 tokenizer 不是 BPE，未知 ID 不是 padding。

## 2. 【面试】为什么先划分训练/验证文本，再拟合词表？

答：只使用训练部分确定字符到 ID 的映射，避免验证信息进入预处理。验证独有字符映射为 0，并报告未知数量。验证只用于评估，不参与参数更新。

易错：先用全文建立词表再划分，会让验证字符影响预处理；当前没有实现变长 padding mask。

## 3. 【必会】训练窗口为什么取 T+1 个 token？

答：每个输入需要一个下一 token 标签。[10,20,30,40,50] 在 T=4 时形成 x=[10,20,30,40]、y=[20,30,40,50]。随机起点抽取 B 个窗口，x/y 均为 [B,T]；模型内部不再移位。

易错：这里随机抽窗口，不是顺序读到某一行；恢复采样状态不是简单恢复文件游标。

## 4. 【必会】训练 loss 评价什么？logits 形状是什么？

答：每个位置损失为 −ln p(真实下一 token)，再对 batch 的位置求平均。B=4、T=32、V=35 时 logits=[4,32,35]，共 128 个监督位置，每个位置有 35 个候选。真实答案概率越高，该位置损失越低。

易错：loss 不是错误数量或准确率；不先 argmax 选词再算交叉熵。

## 5. 【面试】训练 loss 降低为什么不一定表示泛化变好？

答：训练 loss 反映对当前训练样本的拟合，不同步随机 batch 难度不同，单步数值不能直接判断模型优劣。固定小批次 loss 很低而验证变差可能是过拟合。要在一致验证口径下看趋势，并结合数据规模和生成表现。

易错：记住短文本证明训练链路可学习，不证明语言泛化能力。

## 6. 【必会】训练、验证、生成分别输入什么，做什么？

答：训练使用真实历史和下一 token 标签，并反向更新；验证也使用真实文本，但只计算指标、不更新；生成从提示词开始，把选出的 token 接回后续输入，可能选对也可能选错。使用真实历史称为 teacher forcing，它可用于训练或评估。

易错：生成不是特意输入“预测错的词”；固定输入不等于训练。

## 7. 【必会】一次参数更新的顺序是什么？backward 会改权重吗？

答：清理旧梯度 → 前向计算 loss → backward 计算梯度 → 必要的梯度裁剪 → optimizer.step 更新参数。backward 通常把梯度写入参数的 .grad，不直接修改权重；step 才使用梯度与优化器状态更新。

易错：方法名是 backward，不是 backword；loss 有变化不证明已经执行更新。

## 8. 【面试】为什么要 zero_grad？什么情况允许累加？

答：PyTorch 默认累加梯度。旧梯度 2、新贡献 0.3，不清理会得到 2.3。当前每步独立更新，使用 zero_grad(set_to_none=True) 清理；有意的梯度累积可以跨微批次保留梯度，但要设计损失缩放与更新频率。

易错：清的是梯度，不是参数；当前没有完整梯度累积选项。

## 9. 【面试】AdamW 保存什么历史？权重衰减是每步减 1% 吗？

答：AdamW 保存梯度一阶与二阶矩估计等，用历史方向与尺度调整更新，并施加与自适应梯度更新解耦的权重衰减。只恢复参数会丢失优化历史。weight_decay=0.01 不等于每步直接缩小 1%，收缩还与学习率有关。

易错：AdamW 不只看当前梯度；它的解耦权重衰减不能简单说成与向 loss 加 L2 完全等价。

## 10. 【必会】warmup 与余弦学习率有什么作用？

答：初期逐步提高学习率，之后平滑下降到最低值。学习率过大可能震荡/发散，过小可能学习缓慢。当前函数使用全局 step 与原计划总步数，因此恢复要保持这套进度定义。

易错：更大学习率不保证更好；训练 warmup 与性能测试预热不同。

## 11. 【面试】eval 与 no_grad 有什么区别？为什么恢复模式？

答：eval 改变模块训练/评估行为，例如影响 Dropout/BatchNorm，但不关闭求导；no_grad 禁止作用域中的梯度记录，但不切换模块模式。评估同时使用二者，并在 finally 恢复原 model.training。no_grad 作用域退出后梯度模式会恢复。

易错：不能说 eval 使之后永久无梯度；当前模型没有 Dropout/BatchNorm，仍保留规范的模式管理。

## 12. 【面试】验证为何使用独立固定随机生成器？

答：每次验证创建相同种子的生成器，抽到同样窗口以降低样本变化噪声；独立于训练采样器，不消耗训练随机流。当前验证是固定抽样 batch 平均 loss，不是遍历全部验证数据。

易错：固定样本不表示覆盖全面，也不能当作整个验证集精确均值。

## 13. 【面试】autocast 与 GradScaler 各解决什么问题？

答：autocast 根据算子选择合适类型，部分运算低精度以兼顾速度与稳定性，不是所有操作都变 FP16。GradScaler 放大 loss，减少反向小梯度下溢，更新前还原；遇到非有限梯度可跳过更新并调整缩放。当前 FP16 训练只允许 CUDA，CPU 使用 FP32。

易错：缩放不能恢复已丢失信息，也不保证永不溢出；实现接口不等于 GPU 已实测。

## 14. 【必会】为什么先 unscale 再裁剪？混合精度更新顺序是什么？

答：scale(loss).backward() → unscale_(optimizer) → clip_grad_norm_ → scaler.step(optimizer) → scaler.update()。阈值应针对真实尺度梯度，先裁剪放大后的梯度会过度限制更新。全局范数裁剪是超阈值时整体缩放，不是逐元素截到 ±1。

易错：裁剪梯度不等于裁剪权重；scaler.step 可能跳过更新，循环步数不必然等于成功参数更新次数。

## 15. 【面试】完整 checkpoint 应保存哪些内容？

答：模型权重与结构、优化器状态、GradScaler 状态、完成步数、学习率等训练设置、最佳验证成绩、词表和数据指纹、采样器随机状态、PyTorch CPU/CUDA 随机状态。只加载权重可推理或开启新的训练过程，但不能声称接续原优化轨迹。

易错：weights_only=True 是受限反序列化选项，不是只读字典中 model 字段。

## 16. 【面试】为什么恢复时只设 seed 不够？怎样验证恢复一致？

答：seed 决定随机流起点，RNG state 决定当前进度。只设 seed 会重新开始采样，改变后续 batch。应恢复随机状态和优化器等，在同一受控 CPU 环境比较连续 8 步与 4 步保存后恢复至 8 步的参数/状态。当前测试覆盖这种对照。

易错：能继续跑不等于轨迹一致；同 seed 不保证跨版本、设备和所有算子严格一致。

## 17. 【必会】steps、stop-after、last.pt、best.pt 怎么用？

答：steps 是总计划，也影响学习率；stop-after 是本次在某全局步暂停。计划 200、100 暂停，应保留 steps=200 并 stop-after=100。last.pt 对应最近保存点，通常继续训练用它；best.pt 对应最低已观测验证 loss，通常用于选模型。恢复时当前脚本使用 checkpoint 中的训练设置。

易错：best 可能更早；把 steps 改成 100 就改变原学习率计划，不能当成中断恢复对照。

## 18. 【必会】为什么先写临时 checkpoint，再替换正式文件？

答：先完整写到同目录临时文件，再替换正式文件，降低写入中断直接破坏上一份正式 checkpoint 的风险。这提高可靠性，但不是对所有文件系统、断电与并发情形的绝对保证。

易错：可靠保存不能替代完整状态保存。

## 19. 【必会】生成为什么只取最后位置 logits？怎样保留维度？

答：输入 [a,b,c] 时，c 位置输出用于继续整个前缀，并通过注意力参考此前上下文。logits[:, -1, :] 将 [B,T,V] 变为 [B,V]；argmax(-1,keepdim=True) 得到 [B,1]，便于接到 [B,T] 后。ids[:, -1:] 是 [B,1]，ids[:, -1] 是 [B]。

易错：-1 是索引而非输出维度；取最后位置不等于只参考一个 token。

## 20. 【面试】temperature、top-k 和贪心怎样影响生成？

答：本项目 temperature=0 走 argmax；正温度下 logits/temperature，较高温度通常使概率更平缓。top-k 用第 k 高分作阈值，排除更低候选再采样；并列时可能保留多于 k 项。它们不更新权重，当前生成还排除未知 ID 0。

易错：temperature=0 不能直接除；top_k=0 不截断；温度高不保证质量高。

## 21. 【必会】超过窗口时输入和返回序列怎么变化？

答：无缓存每次只输入最近 max_seq_len 个 ID，但返回完整提示词加新增序列。窗口 4、已有 [a,b,c,d,e,f]，本次输入 [c,d,e,f]，返回不会删除前面的 a,b。后续完整缓存满窗会重建以匹配这一基线；预算淘汰另有语义。

易错：返回完整文本不表示模型仍能访问全部历史；当前没有 EOS 提前停止。

## 22. 【面试】怎样证明训练工程有效，并准确介绍它？

答：检查标签对齐、有限梯度和参数更新、固定批次可学习、验证隔离、恢复对照与生成边界，保留真实验证日志。可以介绍字符数据处理、AdamW、学习率调度、裁剪、完整恢复和采样生成；当前证据属于小模型、小语料与 CPU 实验，不代表成熟语言能力、多卡训练或已实测 GPU 加速。

易错：随机模型也能输出文本；只打印“optimizer OK”不代替数值检查。
