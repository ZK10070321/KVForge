# Day 3 简答题复习：参考答案与易错点

## 1. 为什么历史 K/V 可以复用？
答：权重、已有前缀和位置不变时，因果注意力保证历史位置无法看到新增未来 token，因此历史隐藏状态和各层 K/V 不变。
易错：不能只回答“因为已经缓存”；若权重或窗口改变，旧缓存不一定有效。

## 2. 为什么不缓存 Q？
答：新位置的注意力只使用新 Q，查询历史和当前 K，并汇总对应 V。历史 Q 不再参与新位置计算。
易错：不缓存历史 Q 不代表不计算新 Q；新 Q 查询全部可见位置，不只是前一个位置。

## 3. 为什么只输入一个 token 还能利用前文？
答：新增输入长1，但注意力可见的 K/V 包含缓存历史和当前 token。
易错：输入长度不等于可见上下文长度。

## 4. RoPE 的位置怎样处理？
答：历史长P，新输入T个位置时，对新Q/K使用P到P+T-1；历史K已经旋转过，读取时不再旋转。
易错：每步不能从0开始；各层的start相同，不随层编号增加。

## 5. 两个 mask 接口的 True 是什么？
答：F.scaled_dot_product_attention 的布尔 attn_mask=True 表示允许；masked_fill(mask,-inf) 的 True 表示该位置被替换并遮挡。
易错：allowed 交给 masked_fill 时要取反；别推广为所有 PyTorch mask 都具有同一语义。

## 6. 为什么每层缓存独立，长度却统一更新？
答：各层输入与权重不同，K/V不同，所以独立存储；各层处理同一批位置，历史起点相同，所以全部层完成后才统一增加长度。
易错：不能每层都把length增加一次。

## 7. eval 与 no_grad 有什么区别？
答：eval控制模块行为；no_grad关闭计算图记录。生成后恢复原模式，避免影响调用方继续训练。
易错：eval本身不关闭梯度；no_grad作用域退出会恢复之前的梯度状态。

## 8. 怎样取下一个 token 的 logits？
答：logits[:, -1, :]，形状为[B,V]。最后一个位置融合了可见前文，用于预测其后token。
易错：[B,-1,V]不是这个索引结果的形状；最后位置不等于只利用最后token。

## 9. 为什么窗口满后不能简单删除最旧 KV？
答：当前基线重建窗口会重新编号；较深层旧K/V还可能包含已删除token的信息。仅删除缓存项不等价于重算截断窗口。
易错：本项目满窗口后重建，因此此时不再是持续增量加速。

## 10. 相同生成文本能证明正确吗？
答：不能。不同logits可能有相同argmax。应比较所有相关位置的logits，并做因果性和边界检查。
易错：浮点用合理容差；不能随意放宽容差来让错误测试通过。

## 11. 有缓存后每步计算量与历史无关吗？
答：不是。新Q仍读取全部可见K/V，标准稠密注意力这部分成本随历史长度增加。
易错：减少历史位置的重复计算不等于消除关注历史的成本。

## 12. 缓存公式是总显存吗？
答：2×层数×batch×KV头数×位置数×头维度×元素字节数仅计算K/V张量。总显存还有权重、临时张量等。
易错：预分配使用capacity计算分配量；reset只清空有效长度，不清零或释放存储。

## 13. 超过窗口后才不一致，怎么排查？
答：优先检查重建触发时机、reset、最近窗口切片、最新token是否包含、位置重置，以及是否真正重算所有层。
易错：先检查首次出现差异的分支，不要先盲目修改训练参数。

## 14. 小模型开启缓存不变快，是否实现错误？
答：不能直接判断。短上下文省下的计算有限，Python、写缓存、临时张量和窗口重建可能占比较大。先验正确性，再公平计时。
易错：正确性、性能和语言质量是三个不同目标。

## 15. 怎样介绍 Day 3 成果？
答：实现逐层预分配紧凑KV、RoPE偏移和矩形因果遮罩，支持prefill及增量输入。用完整前向对照、不同头配置/后端和生成边界测试验证；Day 1–3的18项测试通过。当前限等长无padding推理，满窗口重建；性能数据另由Day 4评测提供。
易错：不把未实现的高并发、PagedAttention、GPU成绩写成已有成果。
