# Day 5 复习：预算缓存、质量评估与面试问答

阅读顺序：1～9 题掌握策略与位置，10～16 题掌握状态更新，17～28 题掌握评估，最后复习项目表述。重点纠正：保留数量不等于累计数量；dirty 不等于已经出错；预测一致率不等于准确率。
代码：[缓存](../../kvforge/budget_cache.py)、[评估函数](../../kvforge/budget_evaluation.py)、[入口](../../evaluate_budget.py)、[绘图](../../plot_day5.py)、[测试](../../tests/test_day5.py)。结果出处：[原始报告](../../reports/day5_cpu/results.json)。

## 1. 【必会】预算缓存解决什么问题？是否包括当前 token？

答：完整缓存随历史增长，预算缓存限制最多保存 C 个位置的 K/V，满时淘汰旧位置。capacity 包括当前 token，所以“保留旧位置+当前 1 个”不能超过预算。减少历史访问可能影响预测，需要同时评估质量与存储。

易错：不能保留 4 个旧位置再加一个，却仍声称预算为 4。

## 2. 【必会】capacity、length、seen_tokens、next_position 分别是什么？

答：capacity 是保存上限，length 是实际保留数量，seen_tokens 是本轮累计处理数量，next_position=seen_tokens。recent 预算 4，处理完 a～f 后缓存 [c,d,e,f]，四者依次为 4、4、6、6。

易错：length 和 seen_tokens 不能写反；淘汰后原始位置仍增长。

## 3. 【必会】recent 怎样淘汰？

答：未满追加；满时保留最近 capacity−1 个旧位置，再加入当前 token。预算 4、旧 [c,d,e,f]，处理 g 时保留 [d,e,f]，最终 [d,e,f,g]。

易错：当前位置也参与注意力；因果限制禁止未来，不禁止自己。

## 4. 【必会】sink_recent 怎样分配预算？

答：固定保留开头 sink_size 个位置，剩余保存近期位置。满时近期旧位置数量=capacity−sink_size−1，最后 1 个留给当前 token。预算 5、sink_size=2，处理 a～g 后为 [a,b,e,f,g]，原始位置 [0,1,4,5,6]。预算 8、sink_size=2 时近期旧位置为 5 个。

易错：“近期部分”包括当前 token，“近期旧位置”不包括；sink_recent 是策略名，不是数量变量。

## 5. 【面试】为什么 sink_size 小于 capacity？它自动找重要 token 吗？

答：至少给当前 token 一个槽位，故 0≤sink_size<capacity。预算 4、sink_size=3，处理 g 后为 [a,b,c,g]。当前按位置固定开头，不用注意力分数或语义排序；sink_size=0 时规则退化为 recent。

易错：保留开头的设计动机不保证任何模型都获益；本项目不是完整 StreamingLLM 复现。

## 6. 【必会】槽位与原始位置有什么区别？

答：槽位是存储格子，原始位置是输入序号。[a,d,e,f] 的槽位 [0,1,2,3]，原始位置 [0,3,4,5]。处理 g 时保留旧槽位 [0,2,3]，最终 [a,e,f,g] 对应 [0,4,5,6]。

易错：删除内容也要删除位置记录；搬到第 0 格不代表变成原始第 0 个 token。

## 7. 【面试】淘汰后 RoPE 怎样处理，历史 K 是否再旋转？

答：历史 K 已按原始位置旋转，搬动后直接复用，不再旋转。新 Q/K 按 next_position=seen_tokens 旋转一次。所有层对同一新 token 使用同一原始位置。

易错：不能根据 length 给新位置编号，也不能对旧 K 重复旋转。

## 8. 【面试】删除 a 等于忘掉 a 吗？与裁剪文本重算等价吗？

答：不等于。其他 token 在前面层可能已融合 a，后续层的历史 K/V 可能携带这种影响。淘汰只移除直接访问项，不重新计算其他表示；裁剪重算则重建所有层表示。本项目完整生成还会从窗口位置 0 重算，而预算缓存保留原始位置。

易错：不能说第一层每个历史 K/V 都一定包含 a；它们在本层注意力混合之前产生。

## 9. 【必会】固定预算能无限处理输入吗？

答：当前不能。KV 保留数量固定，但 seen_tokens 继续增长，代码仍限制原始位置不超过模型 max_seq_len。

易错：固定内存、长上下文能力和无限流式处理是不同问题。

## 10. 【必会】每层缓存形状是什么？哪些内容可共享？

答：每层 K/V 各为 [B,Hkv,capacity,D]，各层投影和输入表示不同，不能共享数值；位置清单、保留槽位、length、seen_tokens 等可共用。B=2、Hkv=2、capacity=8、D=16 时 K=[2,2,8,16]，有效长度 3 时预分配形状仍不变。

易错：共享调度信息不等于共享表示。

## 11. 【必会】validate、write、commit 分别负责什么？

答：validate 检查归属、模式/梯度、batch、设备/类型、单 token、位置上限与异常状态；write 根据保留槽位更新本层 K/V；全部层和最终输出成功后 commit 正式更新位置、长度和累计数量。

易错：write 已经修改张量，只是计数尚未正式提交。

## 12. 【必会】index_select、copy_ 做什么？预分配是否零临时分配？

答：index_select 沿位置维取出保留槽位，产生选取结果；copy_ 将结果写回已有缓存前部，再写新 K/V。先取出再搬动避免覆盖仍需读取的源数据，但会产生临时存储。

易错：预分配不等于整个过程没有额外张量，KV 字节指标不包含全部临时结果。

## 13. 【面试】为什么不能每层写完就增加 seen_tokens？pending positions 有何用？

答：同一 token 所有层必须用同一位置。第一层用位置 6 后计数加一，会让第二层误用 7，因此最终统一提交。_pending_positions 保存本次新集合的位置，本次注意力使用它，成功提交后成为正式记录。

易错：不能把新 K/V 与旧位置清单配在一起。

## 14. 【面试】dirty=True 表示出错了吗？什么时候清除？

答：表示修改已开始、尚未完整提交，正常调用也会短暂出现。所有层及输出成功后由 commit 清除；中途失败则保留 dirty，拒绝复用并要求 reset。

易错：一层成功不等于整体成功；dirty 标记未提交修改，不等于异常本身。

## 15. 【面试】计数没变为什么仍不能直接重试？reset 是否清零存储？

答：淘汰会原地覆盖数据，可能第 0 层变成 [a,e,f,g]、第 1 层仍为 [a,d,e,f]，保持计数不变无法回滚。reset 将 length/seen_tokens 归零并清理状态，不必释放或清零 K/V；后续只读取重新写入的有效区域。需要原上下文时要重新输入构建。

易错：当前是失败检测与重建，不是完整自动回滚；reset 后 length 是 0。

## 16. 【面试】为什么预算缓存一次只接收一个 token？

答：每个位置需要不同保留集合，例如处理 e 用 [b,c,d,e]，处理 f 用 [c,d,e,f]。逐 token 让状态和参考语义清楚。分块预算可以设计，但要处理块内不同可见集合，当前未实现；完整缓存仍支持分块。

易错：实现范围不等于理论上不可能。

## 17. 【面试】质量评估为什么一直输入真实 token？算训练吗？

答：固定真实历史使不同策略面对相同预测任务，避免生成不同文本后失去控制变量。刚才预测错也继续输入真实 token，即 teacher forcing。此处只前向计算指标，无反向和更新，所以是评估，不直接衡量自由生成文本质量。

易错：固定输入可用于训练或评估，关键看目标与更新流程。

## 18. 【必会】窗口为什么 T+1 个 token？相邻窗口怎样处理？

答：T 个输入需要 T 个下一标签，[a,b,c,d,e] 形成输入 [a,b,c,d] 和目标 [b,c,d,e]。按 T 移动的窗口共享一个边界 token，但目标区间不重复；每窗新建缓存，不继承前窗历史。不足 T+1 的尾部丢弃并报告样本数。

易错：共享边界不等于重复评分；不能把没有下一 token 的最后位置强行计分。

## 19. 【必会】score_from 怎样与标签对齐？

答：按输入位置从 0 编号，取 all_logits[score_from:] 对 window[1+score_from:]。T=4、片段 [a,b,c,d,e]、score_from=2 时，评分输入 c、d 的输出，目标是 d、e。前缀不评分但仍输入模型构建缓存。

易错：只移位一次；不评分不等于跳过计算。

## 20. 【面试】为什么评分共同后缀？16 个位置如何得到？

答：所有策略比较同一批位置，避免不同样本难度干扰。实际 T=32、预算 8/16/24、score_from=24，评分输入 24～31，目标 25～32，三个预算都已进入淘汰阶段。每窗 8 个、2 窗共 16 个，但实际处理输入 64 个。若预算等于整个窗口则不会淘汰，不能推广“都已淘汰”到所有配置。

易错：共同口径不等于样本充分。

## 21. 【必会】评估 logits、targets 的形状和 NLL 公式是什么？

答：单 token 输出 [1,1,V]，取 [0,0] 为 [V]，堆叠为 [T,V]。评分 8 个、V=35 时，交叉熵输入 [8,35]、目标 [8]。NLL=−ln p(真实答案)，reduction='none' 保留逐位置损失，拼接后求平均，不提前 softmax。

易错：真实概率 0.2→0.8 时 NLL 约 1.609→0.223；它不是选错次数。double().mean() 仅提高最终汇总精度。

## 22. 【必会】PPL 怎样计算？能当准确率吗？

答：PPL=exp(平均 NLL)，2.186747 对应约 8.9062。同一数据、tokenizer 和评分口径下越低越好。它不是准确率，也不代表每次恰好在 8.9 个等概率候选中选。先平均 NLL 再指数，不等于逐位置指数后做算术平均。

易错：不同分词和样本的 PPL 不能直接归因于模型能力差异。

## 23. 【面试】delta_nll 为负代表什么？full 必然最好吗？

答：delta_nll=预算 NLL−full NLL。正值本批更差，负值本批更低。full 是基线，不保证模型在每个样本上都能更好利用更多历史；小样本波动也能带来负值。负值不自动说明代码错，也不能证明策略普遍优越。

易错：不要把极小样本负 delta 写成“提升模型精度”。

## 24. 【面试】argmax agreement=100% 是否意味着正确率高、NLL 相同？

答：只说明最高分 token 与 full 相同。真实猫、两者都选狗，则一致但都错；两者都以猫为最高，概率分别 0.8 和 0.6，则都对且一致，但 NLL 不同。

易错：一致率比较两种路径，准确率比较预测和真实标签。

## 25. 【面试】怎样区分实现正确性与策略质量？

答：完整缓存逐 token 应与完整前向数值接近。预算主动改变历史，不要求等于 full；用独立稠密掩码参考，每个查询仅看策略允许位置，与预算输出比较，并测不淘汰等价、容量、位置、失败状态和边界。策略质量另用真实文本 NLL/PPL 和存储衡量。

易错：30 项测试通过不等于语言质量高；跑得快也不能代替正确性检查。

## 26. 【必会】为什么检查字符表和数据指纹，不只检查词表大小？

答：同样大小可能对应不同 ID 含义，例如 ID 5 从猫变狗，权重和标签错位。字符表核对映射，数据指纹核对原实验的数据组合。当前脚本严格使用原训练数据目录是复现约束，不表示模型原则上不能评估新文本。

易错：相同文件名或词表大小不能证明数据一致。

## 27. 【面试】KV 存储公式是什么？减少 75% 意味着什么？

答：同形状各层 KV 字节数=2×L×B×Hkv×capacity×D×每元素字节数，2 是 K 和 V。预算 32→8，16 KiB→4 KiB，节省 1−4/16=75%。这不包括模型参数、位置表、注意力中间量、索引搬动临时张量等，不代表总内存减少 75%。速度还受搬动开销影响，需要另测。

易错：FP32 每元素 4 字节，1 KiB=1024 字节；当前不是 GPU 总峰值显存测量。

## 28. 【面试】sink_recent 一定更好吗？本次能得出什么结论？

答：不一定，固定开头会挤占近期预算，效果依赖模型和数据。预算 8 时 full NLL=2.186747、recent=2.188105、sink_recent=2.202081，recent 在该样本更好。只评分 16 个位置，能验证流程和观察现象，不能宣称普遍优势、几乎无损或统计显著。

易错：不要挑最好的一行，需交代检查点、窗口、预算、评分范围与数量。

## 29. 【面试】下一步怎样增强实验说服力？

答：使用更多独立验证文本和评分位置，覆盖不同预算/sink_size，报告逐窗口差异和不确定性；在模型支持范围内扩展长度；单独测淘汰耗时与内存峰值，区分 KV、元数据和临时开销。若改训练模型或长上下文机制，另行报告，不混入原实验。

易错：这些是后续方向，不是已完成成绩。

## 30. 【面试】怎样用一分钟介绍 Day 5？

答：我实现 Recent 和 Sink＋Recent 固定预算缓存，保留原始 RoPE 位置，采用逐层写入、统一提交与失败重置。用独立掩码参考验证语义，在同一检查点和真实文本共同后缀比较 NLL、PPL、一致率及 KV 存储。预算 32→8 时 KV 存储减少 75%，但当前质量样本仅 16 个位置，不声称普遍无损，也不把存储下降说成总显存或速度提升。

易错：预算缓存尚未接入 generate.py 的命令行默认生成流程，也不支持无限上下文或请求调度。
